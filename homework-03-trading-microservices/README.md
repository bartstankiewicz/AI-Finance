## Logging & audit (PoC)

Every service calls `configure_logging(SERVICE_NAME)` (`shared/trading_shared/logging_config.py`) at startup:

- **structlog -> stdlib logging**: logs go through a non-blocking `QueueHandler`/`QueueListener` to the console
  (human readable) and to `<LOG_DIR>/<service>/<service>.log` (JSON lines, rotated).
- **Audit shipping**: `ErrorLogShipper` (`shared/trading_shared/audit.py`) tails the `.log` file and pushes
  `error`/`critical` lines plus the explicit `SERVICE_RECOVERED` info event to `AuditLogs`.
  Business events such as `trade_opened` or `book_created` remain plain log lines in the file.
- **Audited errors**: use `log_audit_error(log, AuditEventType.X, "Human readable message", entity_type=..., entity_id=..., **payload)`
  (`TRADE_REJECTED`, `STREAM_ERROR`, `DB_PUSH_ERROR`). Any other `log.error` / `log.exception` is stored as `LOG_ERROR`.
- **No lost errors**: shipped byte offset is checkpointed in `<service>.log.checkpoint.json`. After `docker stop`,
  a crash or a DB outage, the next start resumes from the checkpoint (also across rotated files).
  Inserts are idempotent (`audit_id` + `ON CONFLICT DO NOTHING`), so a replay never duplicates rows.
- `docker stop` (SIGTERM) flushes the log queue and makes a final shipping pass before exit.
- Application containers use `restart: unless-stopped`, so Docker restarts them when their main process exits.
  This does not restart a process that is alive but no longer responding; monitoring records `SERVICE_ERROR`
  when it detects the outage and `SERVICE_RECOVERED` when a later health check succeeds.

With Docker Compose, logs are mapped to `./logs` on the host.

| Variable           | Default                          |
|--------------------|----------------------------------|
| `LOG_DIR`          | `/var/log/trading` (Docker), `./logs` locally |
| `LOG_LEVEL`        | `INFO`                           |
| `LOG_MAX_BYTES`    | `10485760` (10 MB)               |
| `LOG_BACKUP_COUNT` | `5`                              |

`monitoring-service` has DB access to query service-error counts and timestamps. Its detected service outages
and recoveries are shipped to `AuditLogs` with the shared file-based shipper.

## Book alpha & beta

`pricing-service` computes alpha and beta **per book** (not per trade) in `app/book_metrics.py` and serves them
on `GET /book-metrics`. The frontend shows them only in the Pricing view (Book risk metrics).

```
beta  = covariance(book_returns, benchmark_returns) / variance(benchmark_returns)
alpha = mean(book_returns) - beta * mean(benchmark_returns)
```

**Benchmark: `S&P500`** (asset class `MARKET_DATA_INDEX`), a synthetic instrument generated by
`market-data-service`, started at the real S&P 500 close of 2026-11-17 (7340.53) and moved by the same random walk
as the other instruments. Why this benchmark:

- the S&P 500 is the standard broad-market reference, so beta reads as "exposure to the market";
- one shared benchmark makes books directly comparable, and it is already in the market data stream
  (no extra source, same tick timing as the book instruments);
- the generator is a placeholder - the symbol can be switched to a real feed without changing consumers.

Limitations: the instruments are generated independently of the index, so betas are expected to be close to 0
(noise) until prices come from real, correlated data. A broad equity index is also a weak reference for
BOND / FX / IRS books; a production system would use one benchmark per asset class.

**Why time series and not just current total PnL and index price**: alpha and beta are statistics of how two
quantities move *together* (covariance, variance, means). A single pair (current PnL, current index price) holds
no information about co-movement; one return needs two consecutive values, and a stable estimate needs many returns.

How the series are built:

- **observation**: one per new benchmark tick (pricing values active trades once per tick round of
  market-data-service). Both returns cover the same interval;
- **benchmark return** = `spot_t / spot_{t-1} - 1`;
- **book return** = change of unrealized PnL of the book's trades valued at both ends of the interval divided by
  their `|fair_value|` at the start. Trades opened or closed in between are excluded, so cash flows (new trades,
  closures) are not counted as performance. IRS trades have `fair_value = NPV` (close to 0), which makes IRS book
  returns noisy;
- **rolling window**: last `ALPHA_BETA_WINDOW = 100` observations per book; alpha/beta are shown once the window
  is full (100 observations, ~17 min at 10 s ticks) and the benchmark variance is non-zero;
- alpha is a mean return **per observation** (shown in %), not annualized;
- series live in memory - a pricing-service restart starts a new window.

| Variable | Default |
|---|---|
| `BENCHMARK_SYMBOL` | `S&P500` |
| `ALPHA_BETA_WINDOW` | `100` |
